# hotarubi

競技かるたの一人練習を支援する、ブラウザ完結型の練習・計測システム。
プロジェクターで畳の上に札を投影し、読み上げに合わせて決まり字が確定した札をハイライトする。
同時に Web カメラで選手の姿勢を記録し、あとから読み札ごとに振り返る。

HCI / インタラクションデザイン領域の研究用システム。研究文脈と設計判断の基準は [CLAUDE.md](CLAUDE.md) にまとめてある。

## 画面構成

| 画面 | 役割 |
| --- | --- |
| `index.html` | **研究者用の操作画面。** プレイヤー・競技・暗記・投影調整・設定の5タブ |
| `projection.html` | **投影用の表示専用画面。** 操作要素を持たない。プロジェクターを繋いだディスプレイに全画面表示する |

選手はアプリを操作しない。選手にとってのインターフェースは投影画面だけ。

投影ウィンドウはタブバー右端の **投影ウィンドウ** ボタンからいつでも開ける。プレイヤーを登録していなくても、カメラを起動していなくても投影と読み上げは動く。

## 必要なもの

- Node.js 18 以上
- プロジェクター（PC のセカンドディスプレイとして接続）
- ノート PC 内蔵の Web カメラ（姿勢推定に使用。外付けカメラや深度センサーは不要）
- インターネット接続（MediaPipe の WASM とモデルを CDN から取得するため）
- OPFS と SharedArrayBuffer に対応したブラウザ（Chrome / Edge 推奨）

## セットアップ

```bash
npm install
```

```bash
npm run dev
```

`http://localhost:5173/` が操作画面。投影画面は「投影調整」タブの **投影ウィンドウを開く** ボタンから別ウィンドウで開き、プロジェクター側のディスプレイに移して全画面にする。

その他のコマンド:

```bash
npm run build
```

```bash
npm run preview
```

## アセットの配置

読手音声と取り札画像はリポジトリに含めていない（`.gitignore` で除外）。以下の場所に自分で配置する。

| 種別 | 配置先 | 命名規則 |
| --- | --- | --- |
| 読手音声 | `public/audio/readers/@03-Yamashita/` | `@03-Yamashita_{NNN}_{P}.ogg` |
| 取り札画像 | `public/images/torifuda/` | `torifuda_F_{N}.jpeg` |

- `NNN` は札番号のゼロ埋め3桁（`000`〜`100`）。`000` は序歌。
- `P` は `1` = 上の句、`2` = 下の句。
- `N` は札番号そのもの（`0`〜`100` の101枚）。`torifuda_F_0.jpeg` は白紙札。**`札番号 − 1` ではない。**

パスの解決は [src/data.ts](src/data.ts) の `audioPath()` / `cardImagePath()` に集約してある。別の読手を使う場合はここを変更する。

`public/data/hyakuninisshu.csv`（札番号・和歌ひらがな・決まり字の3列）だけはリポジトリに含まれている。

## 使い方の流れ

1. **投影ウィンドウ** ボタンで投影画面を開き、プロジェクター側のディスプレイへ移して全画面にする。
2. **投影調整** タブで、プレビュー上の青いハンドルをドラッグして投影エリアの四隅を実際の札の並びに合わせる。台形歪みが残る場合は「行ワープモード」を ON にして各行の左右端も調整する。
3. **暗記** タブで札を並べる。配置パターン A〜D のボタンで自動配置するか、空きマスをクリックして手動で選ぶ。ドラッグで入れ替え、ダブルクリックで削除。並べた内容は即座に投影へ反映される。
4. **競技** / **暗記** タブの読み上げパネルで再生する。序歌 → 上の句 → 下の句の順に進み、決まり字が確定するタイミングで投影側の該当札がハイライトされる。
5. 計測する場合は **プレイヤー** タブで対象者を登録し、**競技** タブでカメラを起動する。カメラを起動しておくと、下の句終了から次の上の句開始後しばらくの間の骨格が `posture_frames` に自動保存される。

1〜4 だけならプレイヤー登録もカメラも不要。

## データの保存先

計測データは OPFS（Origin Private File System）上の SQLite ファイル `/hotarubi.db` に保存される。ブラウザのプロファイル内・オリジン単位の領域なので、次の点に注意すること。

- **オリジンが変わるとデータは見えなくなる。** `localhost:5173` と `localhost:4173` は別物として扱われる。計測時は常に同じコマンド・同じポートで起動する。
- ブラウザのサイトデータを消すと計測結果も消える。
- OPFS には Cross-Origin Isolation（COOP / COEP ヘッダ）が必要。[vite.config.ts](vite.config.ts) で設定済みで、`npm run dev` と `npm run preview` の両方で有効。自前のサーバーに載せる場合は同じヘッダを付けること。付いていない場合はメモリ DB にフォールバックし、**リロードでデータが消える。**

テーブル定義は [src/db.ts](src/db.ts) の `createTables()` にまとめてある。記録した内容をアプリ内で閲覧する画面は用意していないので、分析は DevTools か外部ツールから SQL で行う。読み札ごとのタイミングと配置をまとめた `session_review` ビューを用意してある。
